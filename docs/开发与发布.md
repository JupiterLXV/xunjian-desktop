# 开发与发布说明

## 工程来源与结构

50.4.0 使用桌面 50.3.0 的同步、成果分组和回收能力，合并联网源码 50.2.1 的登录、会话和发布保护。没有修改用户提供的两个原目录。

- `app/main.cjs`：窗口、菜单、IPC、目录授权和关闭保护。
- `app/preload.cjs`：隔离的桌面桥接接口。
- `app/renderer.js`：图片标注、保存队列、草稿、成果分组和刷新。
- `app/desktop-ui.js`：底栏、目录同步调度、回收站和操作记录界面。
- `app/fs-service.cjs`：授权目录内的文件访问、临时写入、提交和日志。
- `app/directory-watch.cjs`：递归监测和目录快照。
- `app/output-trash.cjs`：成果备份、撤回、恢复和中断回滚。
- `app/output-ops.cjs`：分类整理及事务恢复。
- `app/auth.js`：登录页、会话显示、服务配置导入。
- `app/session.cjs`：主进程 24 小时会话、加密持久化及写入授权。
- `app/api-client.cjs`：固定接口、AES-CBC 加解密和网络请求。
- `app/api-settings.cjs`：配置格式校验、系统加密保存和读取。
- `app/api-config.cjs`：仅供开发的本地配置加载器，发布副本替换为空配置。
- `scripts/`：混淆、回归、打包和最终完整性校验。
- `tests/`：单元、Java 互操作及 Electron 桌面流程验证。

## 环境

Windows x64，Node.js 22 或更新版本，npm。`package-lock.json` 锁定依赖；提交时同时维护 package.json 和 lockfile 的版本。

Java JDK 用于 `tests/java-compat.test.cjs` 的双向兼容测试，不是安装包的运行依赖。没有 JDK 时该测试会明确跳过，不应把跳过宣称为兼容性验证通过。

## 安装依赖与开发

```powershell
npm ci
npm test
npm start
```

如果 npm 默认缓存目录不可写，可指定工作目录内的缓存，例如 `npm ci --cache .npm-cache`。不要通过修改全局目录权限来解决本工程的临时缓存问题。

运行后可导入 `api-config.example.json` 所示格式的真实服务配置。开发时还可使用 Git 忽略的 `api-config.local.cjs`：

```powershell
Copy-Item -LiteralPath api-config.example.cjs -Destination api-config.local.cjs
```

然后在本机编辑该文件填入服务根地址及密钥。也支持开发环境变量 `XUNJIAN_API_BASE_URL` 和 `XUNJIAN_API_KEY_BASE64`，不要在日志中打印密钥。

## 接口协议

- 登录：`POST /manage/api/v1/login`，业务字段为 `username`、`password`、`machineCode`。
- 请求体：JSON 字符串形式的 `Base64(16 字节随机 IV + AES-CBC 密文)`。
- 响应：外层成功对象的 `data` 为加密字符串，解密后再按内层 `code === 0` 判断业务成功。
- 主进程从后端 `data.access_token` 建立会话，页面只收到用户名、会话 ID 和有效期。
- `x-auth-token` 保存接口协议保留在 api-client 中；当前保存队列不调用此接口。
- 页面不能指定任意接口 URL，也不会收到服务共享密钥。

## 自动化验证

```powershell
npm test
npm run test:smoke
```

`test:smoke` 用 Playwright 启动真实 Electron，使用 `.qa/` 下独立用户目录、合成图片和本机随机端口模拟后端。通过原生对话框测试替身选择测试目录，实际 IPC、目录服务、加解密、系统安全存储、工作台和文件输出均参与验证。

模拟后端登录后会被关闭，以验证断网本地保存和离线重启。测试入口位于 tests 中，不会打入应用；公开 EXE 仍关闭 Node/远程调试入口。

界面测试输出 `.qa/smoke-report.json` 和截图。单元测试日志可通过 `npm test *> .qa/unit-tests.log` 单独保存；这些本机排查文件不自动提交。测试使用的账号和密钥均为合成值。

## Windows 构建

```powershell
npm run dist
```

生成 NSIS 安装程序。若要同时生成便携版：

```powershell
npm run dist:all
```

其他命令：`npm run dist:dir` 生成解包目录；`npm run dist:portable` 单独生成便携版。构建流程为：

1. 复制 app 到带标记的 `.build/protected`，原始源码保持可维护。
2. 将发布副本的服务配置替换为空对象；真实本地配置和环境密钥都不会打入公开安装包。
3. 混淆 JS/CJS，检查 HTML 不包含内联脚本和内联事件。
4. 对混淆后的代码执行行为回归。
5. 制作 ASAR、Windows EXE、中文 NSIS 和指定的便携产物。
6. 校验实际 EXE 的五个 Electron Fuses、EXE 内嵌 ASAR 摘要、图标、HTML 和全部混淆文件摘要；确认服务配置为空且没有测试或私有文件。

第三方许可 `LICENSE.electron.txt`、`LICENSES.chromium.html` 随应用保留。安装包尚未商业签名。

### 缓存下载故障

若重复下载 Electron 超时，但 `node_modules/electron/dist` 中已有完整的同版本官方运行时，可在 electron-builder 命令中增加 `--config.electronDist=node_modules/electron/dist`。只有在混淆准备和行为回归已经通过后，才直接调用 builder。

如果构建工具解压后遇到 `EXDEV` 缓存重命名错误，可以从 `electron-userland/electron-builder-binaries` 对应 Release 获取工具，在工作区单独解压。必须先与已安装的 app-builder-lib 工具清单中的 SHA-256 核对，再设置其支持的环境变量：`ELECTRON_BUILDER_7ZIP_PATH` 指向 `7za.exe`，`ELECTRON_BUILDER_NSIS_DIR` 和 `ELECTRON_BUILDER_NSIS_RESOURCES_DIR` 指向 NSIS 工具根目录。不要关闭 TLS 或跳过校验。

50.4.0 的本次打包使用官方 7zip 1.0.0 与 NSIS 工具包 1.2.1（NSIS 3.12）。已核验的解包程序可通过 `--prepackaged dist/win-unpacked` 制作安装包；这一步不会重新生成应用代码，之后仍需运行 `node scripts/verify-release.cjs`。

## 数据兼容与变更注意

包名保持 `xunjian-desktop`，appId 保持 `local.xunjian.desktop`，内部应用名称保持“巡检缺陷工具”。因此用户数据继续使用旧路径。

任何新的文件修改 IPC 都需要纳入 SessionService.authorize，尤其不能遗漏独立的回收和恢复入口。已开始的单文件写入允许收尾，新的写入在会话过期时拒绝。

正常卸载保留用户数据，发布产物保留第三方许可。构建清理只应作用于带标记的生成目录。

## 手工发布到 GitHub

本工程公开仓库为 `JupiterLXV/xunjian-desktop`。先完成检查，再提交源码、创建版本标签，并上传安装文件和校验摘要。源码 ZIP 应通过 `git archive` 从发布标签生成，保证不包含 node_modules、私有配置和测试照片。

建议 Release 附件包括安装版、便携版、源码 ZIP、独立操作手册和 SHA256SUMS.txt。发布说明应写明需要导入服务配置、登录后 24 小时离线使用及真实服务未联调等实际边界。

`api-config.local.cjs`、真实服务 JSON、`api-config.bin`、`session.bin`、业务照片和任何账号密码都不能进入公开提交或 Release。
